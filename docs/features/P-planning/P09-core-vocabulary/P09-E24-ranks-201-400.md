# P09-E24. Ranks 201–400 — the same coverage check, one band further

**Feature:** rerun P09's coverage check for COCA lemma ranks 201–400, and turn what is missing into
the same kind of checklist P09 §2 and §3 were.
**Shape:** a research task. Its output is a checklist in this file, then seed tickets and construct
task files filed from it — no code.
**Scope:** English checklist, all 7 languages for whatever it asks to seed (as P09).
**Status:** planning, unscheduled. Filed 2026-09-23 from P09's follow-ups
([README *Follow-ups*](README.md#follow-ups), *Ranks 201–400*).

**The word list is not in this file, and must not be written from memory.** Ranks past 150 shuffle
between corpora and editions (P09 *Why*), so a recalled list would be wrong in ways nobody could
check. The list is **to be fetched and verified** as step 1.

## Why

P09 took the top 200 from "335 concepts, many of them grammar terms" to every word seeded or built.
The next 200 are still everyday vocabulary, and they are the cheapest measurable next step: the
method exists, the source is fixed, and the corpus has doubled since the first check.

## Design

### D1. Fetch the list, record its provenance, keep one source

**Recommendation:** download the COCA lemma list (any edition that reaches rank 400; what is
freely available and under which terms is itself to be checked at download time) and record in
this file the edition, the download date and how ranks 201–400 were cut. Use it alone — no
patching from other lists — so the ranks in the tables are checkable. Check the licence before
committing the file itself; if in doubt, do as P09 did and cite ranks only.

### D2. One row per lemma, P09's convention

COCA ranks lemma + part of speech; a word may occur twice. P09 listed each word once and split
senses in the *proposed id(s)* column (*work* → `WORK`, `WORK_NOUN`). **Recommendation:** the same,
and say in the checklist's header which convention was used, since it decides the counts.

### D3. Mechanical first, judgement second

1. A throwaway script (scratchpad `.mts` run with `tsx`, per the probe-render habit) imports
   `concepts` from [`concepts/index.ts`](../../../../packages/backend/src/concepts/index.ts) and
   prints every concept's English `base` (and plural, for nouns), then marks each list lemma
   **seeded** (exact base match, or a known form — *people* of PERSON), **pronoun form**, or
   **unmatched**.
2. Unmatched lemmas are grepped in the English engine sources for **written by the engine**.
3. What is left is read by hand into **left to seed** (a `/seed` row) or **needs the engine first**
   (a construct), applying P09 §1's decisions: D1 (a close seeded concept may cover it), D2 (one
   concept per meaning), D3 (particles become phrasal verbs).

The script is not committed; its output is.

## 1. Deliverable

A checklist in this file's `## Done`, shaped as P09's:

- the status table (*count*, *words*) with the five buckets;
- §2-style tables per role — *rank*, *en*, *proposed id(s)*, *notes* — each row a `/seed` candidate
  with its sense split and any language divergence;
- a §3-style table of constructs — *#*, *construct*, *words*, *notes* — one row per construct, never
  bundling unrelated ones.

Then, per the localization protocol, the seed rows are catalogued as B tickets and each construct
gets a task file here (P09-E25 onwards), each with a *Today* verified at HEAD.

## Verification

1. The checklist header names the list's edition and date; every rank in it can be found in that file.
2. Every *seeded* claim resolves to a concept id in `packages/backend/src/concepts/` at the commit the
   checklist cites.
3. Every *written by the engine* claim names the source file that writes the word.

## Out of scope (follow-ups)

- **Seeding** the words found — B tickets, not this task.
- **Building** the constructs found — their own task files.
- **Ranks 401+**, and a spoken-English list (P09 *Why* on *yeah*, *oh*, *got*).
